How to read this

  • Two schedules, one graph. /start-all schedules every ticket from this graph, gated only by blocked_by — module boundaries never gate anything. /start-milestone runs one module at a time, so a barrier sits between modules and concurrency fans out only within the one running. Both are executable; the difference is what running module by module costs on this decomposition.
  • Dashed edges cross a module boundary. They are real blocked_by dependencies, and /start-all enforces them directly. Running module by module additionally serializes tickets with no edge between them at all, which is where the extra rounds come from.
  • The DAG is live during a run. /start-all reloads it every few settled tickets, so a ticket added while it runs is published, scheduled, and rendered here on the next reload. A dependency added to a ticket that already started cannot be applied retroactively — the run escalates it instead of pretending it was enforced.
  • Max useful lanes is the lowest concurrency that still reaches the minimum round count. Above it lanes sit idle; below it, independent tickets are serialized.
  • Uniform-duration model. Every ticket counts as one round and a wave ends when all its lanes finish. Real lanes finish at different times and the scheduler refills a free lane immediately, so real wall-clock is at most the rounds shown.
  • A fully serial module is a decomposition problem, not a scheduling one. Its tickets form one blocked_by chain — revisit the file-scope split before signing off.
  • Color covers the first 4 modules only. Cards from any two modules can sit side by side, so the palette must clear the all-pairs contrast floors; 4 is the largest set that does in both light and dark. Module 5 onward take the neutral swatch — identity comes from the chip on every card, the legend, and click-to-highlight, never from hue alone.
  • Caps that still apply at run time: supervised mode forces concurrency to 1, and the harness caps concurrent agents at min(16, cores - 2) on the machine that runs it. That machine is unknown here, so it is shown as a formula rather than a number.
  • Regenerate with node .claude/scripts/dag-report.mjs after any ticket blocked_by change. Output is deterministic — an unchanged DAG rewrites an identical file.
